
# Bitonic Sorting Network Hardware Generator (Rust to VHDL)

![Rust](https://img.shields.io/badge/rust-%23000000.svg?style=for-the-badge&logo=rust&logoColor=white)
![VHDL](https://img.shields.io/badge/VHDL-00599C?style=for-the-badge&logo=v&logoColor=white)
![FPGA](https://img.shields.io/badge/FPGA-Xilinx_Artix--7-red?style=for-the-badge)

A custom Electronic Design Automation (EDA) tool written in **Rust** that dynamically generates synthesizable, fully-pipelined **VHDL** code for a Bitonic Sorting Network. The project includes a complete hardware wrapper to test the generated core on a **Basys 3 (Artix-7) FPGA** using a 7-segment display.

## Why Bitonic Sort in hardware?
In software, algorithms like Quicksort O(N * log N) are preferred. However, in hardware design, data-dependent branching (if/else statements based on array values) ruins parallel performance and makes physical silicon implementation highly inefficient.

**Bitonic Sort** is a parallel sorting algorithm that performs exactly the same sequence of comparisons regardless of the input data. This deterministic, data-independent behavior makes it the perfect candidate for hardware acceleration.

## Key features
* **Automated VHDL Generation:** Writing structural VHDL for large sorting networks is tedious and error-prone. This Rust tool calculates the mathematical topology of the network and writes the VHDL automatically based on parameterized inputs ($N$ elements, $W$ data width).
* **Fully Pipelined Architecture:** The generator automatically inserts pipeline registers (Flip-Flops) between every comparator stage. 
* **Extreme Throughput:** Thanks to the deep pipelining, the core achieves a throughput of **1 fully sorted array per clock cycle**. Running at 100 MHz on the Basys 3, it can perform **100 million sorts per second**.
* **Hardware-Ready I/O:** Includes hand-written VHDL modules (Double Dabble BCD converter, 7-segment multiplexer, and button debouncers) to visualize the sorted data on real hardware.

## Repository structure

The repository is divided into two main parts: the Rust generator and the VHDL hardware implementation.

```text
├── Cargo.toml                 # Rust project configuration
├── src/
│   └── main.rs                # The Rust Hardware Generator (EDA tool)
└── vhdl/                      # VHDL source files for Vivado
    │ 
    ├── [ Generated by Rust ]
    │   ├── bitonic_network.vhd # The core pipelined sorting network
    │   ├── comparator.vhd      # Basic compare-and-swap module
    │   ├── sorter.vhd          # Top-level wrapper for the generated network
    │   └── tb_network.vhd      # Automated testbench for simulation
    │
    └── [ Hand-written for Basys 3 I/O ]
        ├── network_types.vhd         # Custom types/arrays package
        ├── binary_to_bcd.vhd         # Double Dabble algorithm for decimal conversion
        ├── seven_segment_display.vhd # 7-segment display multiplexer controller
        ├── seven_segment_encoder.vhd # Hex/BCD to 7-segment decoder
        └── push_btn.vhd              # Button debouncer/synchronizer
```

## How to use

### 1. Generate the hardware (Rust)
Ensure you have Rust and Cargo installed. Clone the repository and run the generator:
```bash
cargo run
```
This will execute `src/main.rs`, calculate the comparator topology for $N=8$ (configurable in the source), and output the synthesizable VHDL files into the `vhdl/` directory.

### 2. Implement on FPGA (Vivado)
1. Create a new RTL project in Xilinx Vivado targeting the **Basys 3** board (xc7a35tcpg236-1).
2. Add all the `.vhd` files from the `vhdl/` directory as design sources.
3. Set `sorter.vhd` (or your custom top module) as the Top Module.
4. Add your Basys 3 `.xdc` constraints file (mapping the clock, buttons, and 7-segment display pins).
5. Generate the bitstream and program the device.

## ⚠️ Synthesis optimization note 
If you synthesize the generated code exactly as it comes out of the Rust tool, you might notice an abnormally low LUT/FF utilization in Vivado's reports. 

This happens because the Rust generator hardcodes the random input numbers into the `inputs` array inside `sorter.vhd`. Vivado's synthesizer is smart enough to perform **Constant Propagation**: it realizes that if the inputs never change, the sorting result will always be the same. Therefore, Vivado pre-calculates the sorted array during synthesis, deletes all the physical comparators and pipeline flip-flops, and replaces the entire Bitonic Network with hardwired constants connected to VCC/GND.

**To force Vivado to build the actual physical sorting network**, you must ensure the inputs are dynamic (not known at compile time). You can do this by mapping at least one of the inputs to the physical switches of the FPGA, or by feeding the network with a continuously running LFSR. 

For example, in `sorter.vhd`:
```vhdl
-- Replace a hardcoded constant with a dynamic physical input
inputs(0) <= sw(15 downto 0); 
```
Once the inputs are dynamic, Vivado will be forced to synthesize the full parallel comparator topology and the shift registers.
